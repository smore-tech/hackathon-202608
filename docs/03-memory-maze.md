# 企画3：「見えない迷路」記憶ゲーム

> プロトタイプ: [../memory-maze/index.html](../memory-maze/index.html)

## 1. 一言で説明

**「迷路が見えるのは最初の3秒だけ。あとは記憶だけを頼りにゴールを目指す」** ゲーム。

## 2. ゲームの目的

左上からスタートし、右下のゴール 🏁 に到達する。

ただし壁が見えているのは開始直後の数秒だけで、その後は真っ暗な格子だけが残る。壁にぶつかっても止まるだけでゲームオーバーにはならないが、「壁ドン回数」としてカウントされる。

クリア時に **移動回数・壁ドン回数・タイム** が出る。少ないほど「ちゃんと覚えていた」ことになる。

## 3. 基本ゲームループ

```text
STARTを押す
↓
迷路が表示される（3秒のカウントダウン）
↓
壁が消える
↓
記憶を頼りに1マスずつ進む
↓
壁にぶつかる（ミス+1／ぶつかった壁だけは以後ずっと見える）
↓
ゴール到達 → 移動回数・壁ドン・タイムを表示
↓
Retry（同じ迷路） / 新しい迷路
```

## 4. プレイヤーが考えること

- **覚え方を自分で発明する。** 3秒では全部は覚えられないので、人は勝手に省略をはじめる。「右右下下、そのあと左」のように **経路を手順の列に圧縮する**。迷路を覚えているのではなく、自分の行動計画を覚えている。
- **どこまで覚えたかを自己申告する。** 「最初の4手は確実、その先はあやしい」という自覚がある状態で歩き出す。この「確信が減っていく感覚」がゲームの体験そのもの。
- **壁にぶつかった瞬間、記憶を上書きする。** 「ここは通れないのか」という情報が入り、頭の中の地図が修正される。ここで悔しさと納得が同時に来る。
- **迷ったときに賭ける。** 記憶が尽きた地点で、「たぶんこっち」を選ぶ。当たれば嬉しく、外れれば自分のせい。
- ゴールが常に右下と分かっているので、**迷ったら右か下** という保険が常にある。この保険があるおかげで完全に詰まらない。

## 5. 面白さの仮説

- **ルール説明が要らない。** 「迷路」「覚える」は誰でも知っている。1秒で理解できる。3案の中で理解コストが最も低い。
- **壁が消える瞬間に体が緊張する。** カウントダウン → 消失 → GO の流れが、そのまま集中のスイッチになる。
- **失敗が完全に自分のせい。** 運の介在がゼロなので、「もう1回覚えれば勝てる」と即座に思える。リトライの動機として一番素直。
- **数字で腕前が出る。** 壁ドン0回でクリアできると気持ちいい。スコアが自然に定義できるので、Daily Challenge やランキングに素直に載る。
- 同じseedなら同じ迷路が出るので、「全員が同じ迷路を解く」形式にそのまま乗せられる。

## 6. 不安要素

- **記憶ゲームは人を選ぶ。** 覚えるのが苦手な人は最初の1問で心が折れる可能性がある。
- **記憶せず総当たりで進めてしまう。** 壁にぶつかってもペナルティが軽いと、覚えるより手当たり次第に進むほうが速い、という攻略が成立してしまう。
- **画面が空っぽになる。** 壁が消えた後の画面は格子とマーカーだけで、絵として持たない。
- **難易度の刻みが荒い。** サイズと表示時間しか調整軸がなく、5×5と7×7の間の体感差が大きい。
- ゲーム性が素直すぎて、独自性が弱い。「見たことある」と言われやすい。

## 7. 1日ハッカソンでのMVP

- 穴掘り法（DFS）による迷路生成 + seed による再現
- 迷路の描画（CSSのborderで壁を表現）と、壁の表示/非表示の切り替え
- カウントダウン付きの記憶フェーズ → 操作フェーズへの遷移
- 移動処理と壁判定（矢印キー / WASD / 画面上の方向ボタン / スワイプ）
- 移動回数・壁ドン回数・タイムの計測と、クリア時の表示
- Retry（同じ迷路） / 新しい迷路

## 8. 時間が余ったら追加するもの

優先順位順。

1. **スコア化。** 「移動 + 壁ドン×3 + 秒数」程度の1つの数字にまとめる。総当たり攻略を潰し、比較可能にする。効果が最も大きい。
2. **難易度セレクタ**（プロトタイプでは実装済み。5×5 / 6×6 / 7×7）。
3. **チラ見ボタン**（1回だけ壁を再表示、ただしミス+5）。記憶が尽きた時の救済と、駆け引きを同時に作れる。
4. 経路長の制御（プロトタイプで実装済み。曲がりすぎる迷路を弾く）。
5. アイテムマス（途中の⭐を拾うとボーナス）。ゴール直行以外の選択肢が生まれる。
6. 効果音（壁ドンの「ゴツン」）。悔しさが増して良い。

## 9. 将来的な拡張案（今回は実装しない）

- **Daily Challenge**：日付から seed を作り、全員が同じ迷路を解く。この案が最も自然に乗る形式。
- **SNS共有**：`壁ドン 2回 / 18歩 / 24.3秒` のような結果カードを絵文字で。Wordle 型の共有と相性が良い。
- **Seed / URL共有**：`?seed=12345` で友達に同じ迷路を送る（プロトタイプの seed 表示は既にこの布石）。
- **Ranking**：Dailyのスコア順位。
- **ステージエディタ**：手描き迷路の投稿。
- **モード追加**：暗闇モード（自分の周囲1マスだけ見える）、逆走モード、移動するゴール。
- **難易度の自動調整**：クリア成績に応じてサイズと表示時間を動的に変える。

## Prototype Review

実際にブラウザで5×5〜7×7を何度か遊んだうえでの所感。企画時点の想像とは分けて書く。

### 実際に触ると何が良かったか

- **壁が消える瞬間の「あっ」がちゃんと来た。** カウントダウン 3 → 2 → 1 のあいだ必死に目で追い、消えた直後に「今の何だっけ」となる。この数百ミリ秒だけで企画の芯は成立している。
- **3案の中で、説明が最も要らなかった。** START を押した人が、何も言われずに正しく遊びはじめられる。
- **「ぶつかった壁だけ以後ずっと見える」仕様が想像以上に良かった。** 実装は数行なのに、失敗が地図として画面に残るので、リトライのたびに前回の知識が積み上がる。壁ドンが単なる罰ではなく、情報を買う行為に変わっている。
- クリア時に壁を全部表示する「答え合わせ」も効いた。自分の記憶がどこでズレたかが一目で分かる。
- seed 表示のおかげで「同じ迷路をもう一度」が自然に成立し、Daily 化の相性の良さが触った段階で確認できた。

### 想定より弱かった部分

- **最初に作った迷路が難しすぎた。** 素の穴掘り法（DFS）で作ると、5×5でも最短経路の中央値が14手あり、曲がりが多すぎて3秒ではまったく覚えられない。**経路長に上限を設けて生成し直す処理を足すまで、ゲームとして成立していなかった**（上限を入れた結果、5×5の中央値は10手になった）。難易度は「サイズ」ではなく「経路の形」で決まる、というのは触るまで気づけなかった。
- **総当たりで押し切れてしまう。** 壁ドンにペナルティがないので、覚えるのを放棄して片っ端から進んでも、10回くらいぶつかれば必ずゴールできる。しかも記憶するより速い。**懸念として書いた「覚えずに突破される」は、実際にやってみると本当に最適解になっていた。**
- **歩いている最中の画面が本当に空っぽ。** 通ったマスに薄い点を残す処理を足してもまだ寂しい。プレゼンで後ろから見ている人には何が起きているか伝わらない。
- 記憶が尽きた後の「勘で進む」時間が、思ったより長い。ここが単調になりやすい。

### 本制作するなら最初に改善したいところ

1. **壁ドンに実質的なコストを付ける。** 単一スコア（例：`歩数 + 壁ドン×3 + 秒数`）を出すだけで、総当たりが最適解でなくなる。この1点だけで、記憶ゲームとして成立するかどうかが決まる。最優先。
2. **迷路生成を「覚えやすさ」基準で設計し直す。** 経路長の上限だけでなく、曲がり回数を難易度パラメータにする。「5×5で3回曲がる」のように指定して生成できると、難易度カーブが素直に引ける。
3. **歩行中の画面を持たせる。** 通過済みのマスを線でつなぐ、残り歩数の目安を出すなど、暗闇でも状況が見える表現がいる。
4. 「チラ見（ミス+5）」を入れる。詰みの救済と、使うかどうかの葛藤を同時に作れて安い。

## 実装版（GitHub Pages 公開版）で何が変わったか

| | Mock | 実装版 |
| --- | --- | --- |
| ステージ | 3サイズ（5×5 / 6×6 / 7×7） | **12ステージ**（4×4 〜 9×9、モード違いを含む） |
| モード | ふつうのみ | **ふつう / 鍵あり / ライフ制 / 鍵＋ライフ** の4モード |
| 目標 | ゴールに着くだけ | 最短歩数を表示し、`歩数 + 壁ドン×3` をスコア化 |
| 評価 | なし | ★3段階（★★★＝最短歩数かつノーミス） |
| 記録 | なし | localStorage にステージ別ベストスコアと★を保存 |
| 共有 | なし | **seed をURLに載せて同じ迷路を共有**できる |

### 実装のポイント

- 迷路は seed から完全に再現できる（`mulberry32` + 穴掘り法）。
  だから「同じ迷路で勝負」がサーバーなしで成立する。
- 鍵は「スタートからもゴールからも遠いマス」を決定的に選ぶ。乱数で置くと簡単すぎる位置に出てしまう。
- ステージごとに `maxPath`（必要歩数の上限）を持ち、条件を満たす迷路が出るまで seed を進める。
  曲がりくねりすぎて**覚える気が失せる迷路を出さない**ためのガード。
- 「生成した迷路が完全迷路である（全マスに行ける・閉路がない）」ことは CI のテストで検査している。
