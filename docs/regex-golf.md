# Regex Golf

> Mock: [../regex-golf/index.html](../regex-golf/index.html)

## Elevator Pitch

**「この3つには当たって、この3つには当たらない正規表現を、できるだけ短く書け」**

```text
MATCH          user_123  user_456  user_999
DO NOT MATCH   admin_123 user_abc  guest_123
```

素直に書けば `^user_\d+$`（10文字）。でも `r_\d`（4文字）でも通る。

## Core Loop

```text
URLを開く（MATCH / DO NOT MATCH のリストが復元される）
↓
共通点と差分を探す
↓
正規表現を打つ（打つそばから ✅ / ❌ が更新される）
↓
全部 ✅ になったら CLEAR
↓
文字を削る（PAR を切りにいく）
↓
SHARE URL ／ REMIX してテストケースを足す
```

## Fun Hypothesis

- **RUN ボタンが要らない。** 1文字打つたびに判定が更新されるので、フィードバックのレイテンシがほぼゼロ。3案で最も速いループ。
- **「短くする」の余地が桁違いに大きい。** 総当たり解が32文字、賢い解が4文字。1桁縮む快感がある。
- ❌ の行がそのままヒントになる。「`user_` だと `user_abc` にも当たってしまう」→「じゃあ数字を要求すればいい」と、次の一手が画面から読める。
- 正規表現は多くのエンジニアが「なんとなく書ける」ものなので、腕前の差がそのまま文字数の差として出る。マウントも取れるし、感心もできる。

## Engineer Appeal

- 説明が一切要らない。`MATCH` / `DO NOT MATCH` の2列を見せれば、それだけでルールが伝わる。
- 正規表現は「知っている人ほど短く書ける」領域なので、**知識がそのままスコアになる**。エンジニア同士の会話が生まれやすい。
- 「これ、`\b` 使えばもっと短いよ」のような横やりが入る余地がある。観戦・野次が成立する。
- Challenge 作成が2つのテキストエリアだけで済むので、思いついた瞬間に問題にできる。

## Sharing Loop

`{match, reject, par}` だけなので、URLは200〜300文字程度。

```text
A が「これ何文字で書ける？」と URL を投げる
↓
B が 11 文字で解く → 「9でいけた」と C が割り込む
↓
誰かが REMIX して DO NOT MATCH を1件足す
　→ さっきの短い解が通らなくなる → 新しい URL
```

**Remix が「テストケースを1件足す」という形になる**のがこのゲームの特徴で、これは「短すぎる解（チーズ解）を潰す」行為そのもの。共有の連鎖が、そのまま問題の品質向上になる。3案で唯一、Remix に**改善の方向性**がある。

## MVP（1日ハッカソン）

1. MATCH / DO NOT MATCH の2列表示
2. 正規表現の入力欄（文字数制限あり）と、入力ごとのリアルタイム判定
3. 各行の ✅ / ❌ 表示
4. 不正な正規表現のエラー表示（例外を投げない）
5. CLEAR 判定と Regex Length / PAR / PAR差 の表示
6. URL fragment への保存・復元（version・type・壊れたら DEFAULT）
7. CREATE モード（2つの textarea + PAR）と SHARE URL
8. REMIX
9. サンプル3問

## Cut List（上から捨てる）

1. **AUTO PAR（総当たり解の長さを計算）** — 手で入れてもらってよい
2. **PAR そのもの** — 「何文字で解けた」だけでも競争は成立する
3. **リアルタイム判定** → 「TEST ボタンを押したら判定」に落とす（体験は大きく落ちる）
4. **COPY RESULT**
5. **重複チェックなどの入力バリデーション**
6. サンプルを3問 → 1問に減らす

## Expansion（今回は実装しない）

- **Daily Regex**：1日1問。全員の最短文字数を並べる。
- **フラグの解禁**：`i` フラグを使うと +2 文字ペナルティ、など。
- **禁止文字ルール**：「`\d` 禁止」「`|` 禁止」などの縛りモード。ゴルフの定番。
- **段階的ヒント**：詰まったら DO NOT MATCH が1件減る（ペナルティつき）。
- **チーズ解の自動検出**：作成時に、意図しない極端に短い解が存在しないかを軽く探索して警告する。
- **Ranking / SNS共有**：`11 chars` の絵文字カード。
- **逆モード**：与えられた正規表現に対して、MATCH / DO NOT MATCH の文字列のほうを考える。

## Prototype Review

Mock を実際に触ったうえでの記録。企画時点の期待と、実装後に分かったことを分けて書く。

### 触ってみて良かった部分

- **リアルタイム判定の速さが、想像より効いた。** `u` → `us` → `use` と打つあいだに ✅ と ❌ がパタパタ切り替わる。RUN を押す必要がないぶん、3案で圧倒的に試行回数が多くなる。**1問あたりに試した回数は Route Golf の3倍以上**だった。
- **`r_\d`（4文字）を見つけた瞬間が、今回のMock全体で一番の「うおっ」だった。** PAR 32 に対して `PAR -28` が出る。企画時に「1桁縮む快感」と書いたが、実際には想像より気持ちよかった。しかも見つけ方が「盤面をよく見る」ではなく「思いつく」なので、成功が完全に自分の手柄に感じられる。
- **失敗が的確にヒントになる。** `user_` と打つと `user_abc` の行だけが赤くなる。**次に何をすべきかが画面に書いてある**に等しい。
- **Create が3案で最も簡単。** テキストエリア2つに文字列を並べるだけ。実装も一番軽い。

### 想定より弱かった部分

- **画面がまったく動かない。** テキストのリストに色が付くだけ。企画時に「デモとして地味すぎないか」を検証項目に挙げたが、**Pipeline Golf よりさらに地味**というのが結論。プロジェクターに映しても、後ろの席では ✅ と ❌ の区別すらつかない可能性がある。
- **チーズ解の問題が想像より深刻。** `r_\d` は確かに正解だが、これは「正規表現が上手い」というより「テストケースが弱い」ことの証明でもある。**短い解を見つけた喜びと、問題が雑だった落胆が同時に来る。** 良い Challenge を作るにはテストケースの設計力が要り、これは Route Golf で壁を1個置くのとは比べものにならない負荷。
- **解けた瞬間に終わる。** Route Golf のように「もう1命令削れないか」を粘る感じが薄い。4文字まで縮んだ時点で、それ以上は縮まないと直感的に分かってしまう。**「もう一回」の持続時間が3案で最も短い。**
- **非エンジニアが完全に締め出される。** 正規表現を知らない人にとっては、画面に手がかりが1つもない。3案で唯一、遊べる人を選ぶ。

### 操作して気持ちよかった部分 / 面倒だった部分

- 気持ちよかった：文字を1つ消したら文字数カウンタが減り、それでも全部 ✅ のままだったとき。
- 面倒だった：特になし。**3案で最も摩擦の少ない操作**だった。入力欄が1つしかないので、迷う場所がない。

### 「もう一回」を感じたか

**問題単位では強く、ゲーム単位では弱い。** 1問を解くあいだの試行回数は最も多いが、解き終わったあと「次の問題を作ろう」とはあまり思わなかった。良い問題を作るのが難しいと分かっているから。

### Challenge を誰かに送りたいと思えるか / Remix したくなるか

- 送りたい：**強く思える。** ただし相手は限定される。「エンジニアの同僚」には送りたいが、それ以外には送りようがない。
- Remix したい：**思える。しかも動機が3案で一番健全だった。** `r_\d` で通ってしまったので、DO NOT MATCH に `car_1` を足したくなる。**Remix が「問題を良くする」方向に働く**のは、触ってみて初めて気づいた性質で、企画書には書いていなかった。この点だけは3案で明確に優れている。

### ハッカソン本番で作る価値があるか

**単独の企画としては弱い。** 実装は最も軽く（1〜2時間で動く）、エンジニア受けは最も高いが、**ハッカソンの成果発表という場でスクリーンに映して伝わらない**のは大きい。

ただし、
- 「URL共有 + Code Golf」というコンセプトの検証としては最も純度が高い
- Route Golf を本命として作りきったあとの**2本目**として足すなら、実装1〜2時間でラインナップの厚みが増す

という位置づけなら価値がある。単独本命ではなく、サブとして考えるのが妥当だと触ってみて感じた。
