# Route Golf

> Mock: [../route-golf/index.html](../route-golf/index.html) ／ 3案の中の**最有力候補**

## Elevator Pitch

**「F・L・R だけでロボットをゴールへ運ぶ。使った命令が少ないほど強い」**

盤面はURLに入っている。URLを送れば、相手も同じ盤面で「もっと短く解けないか」を始められる。

## Core Loop

```text
URLを開く（盤面が復元される）
↓
盤面を見て、頭の中でルートを引く
↓
F / L / R を並べてプログラムを組む
↓
RUN
↓
CRASH / NO GOAL / CLEAR
↓
命令を削る（PAR を切りにいく）
↓
SHARE URL ／ REMIX して自分の盤面を作る
```

## Fun Hypothesis

- **RUN を押した瞬間に、自分の書いたものが物理的に動く。** これはコードを書いて実行する体験そのもので、かつ結果が1〜3秒で目に見える。テストが通る瞬間の圧縮版。
- **失敗の種類が2つしかない**（CRASH / NO GOAL）。どちらも原因が盤面上の1点に特定できるので、「なぜ落ちたか分からない」がほぼ起きない。
- **クリアがゴールではない。** クリアした瞬間に「あと1命令削れないか」が始まる。ここでゲームが2周目に入る。
- スコアが「命令数」という整数1個なので、比較が一瞬で終わる。`8 commands` と言われれば、7で解けるか試したくなる。
- 盤面を作るのも簡単。壁を1個足すだけで別の問題になる。

## Engineer Appeal

- 命令列 = プログラム。**書く → 実行 → 落ちる → 直す** という日常のループがそのままゲームになる。
- 最短手数はBFSで求まる問題であり、「人間の直感 vs 最適解」の勝負として理解しやすい。
- PAR という共通の物差しがあるので、Slackに `7 commands (PAR -1)` と投げるだけで会話が始まる。
- ステージエディタが「自分の問題を人に解かせる」欲求を直接満たす。エンジニアはこれを好む。

## Sharing Loop

URL fragment に `{w,h,walls,sr,sc,sd,gr,gc,par}` を入れるだけなので、5×5の盤面で **約150文字**、7×7でも200文字前後に収まる。Slack / X にそのまま貼れる長さ。

```text
A が盤面を作る → URL を貼る
↓
B が解いて「PAR -1 出た」と返す
↓
A が REMIX して壁を1個足す → 新しい URL
↓
B も REMIX する
```

**元の Challenge を書き換える概念がない**のが重要で、REMIX は常に新しいURLを発行する。壊れる心配がないので、気軽に改変できる。

## MVP（1日ハッカソン）

1. 盤面の描画（壁 / スタート＋向き / ゴール）
2. F・L・R の命令入力、プログラム表示
3. RUN（1命令ずつのアニメーション + 実行中の命令ハイライト）
4. CLEAR / CRASH / NO GOAL の判定
5. Commands / PAR / PAR差 の表示
6. URL fragment への Challenge 保存・復元（Base64URL・version・type・壊れたら DEFAULT）
7. CREATE モード（盤面編集・向き・PAR）と SHARE URL
8. REMIX（現在の Challenge を CREATE に流し込む）
9. サンプル3問（Easy / Medium / Hard）

## Cut List（時間が足りないとき、上から捨てる）

1. **STEP ボタン** — RUN があれば実用上ほぼ困らない
2. **UNDO** — CLEAR PROGRAM で代用できる
3. **移動アニメーション** — 瞬間移動でも成立はする（ただし面白さは大きく落ちるので最後まで残したい）
4. **grid size の可変**（5×5固定にする）
5. **COPY RESULT**（SHARE CHALLENGE だけ残す）
6. **AUTO PAR / SOLVABLE 判定** — ただしこれを捨てると壊れた Challenge が共有され得るので、捨てる優先度は最低にすべき

## Expansion（今回は実装しない）

- **命令の拡張**：`F3`（3歩前進）、`[...]×n` のループ、条件分岐 `IF WALL`、サブルーチン。プログラミング要素を段階的に足せる。
- **ギミック**：一方通行タイル、ワープ、押せるブロック、鍵と扉、収集アイテム（全部拾ってからゴール）。
- **Daily Route**：日付から seed を作って全員が同じ盤面を解く。
- **Leaderboard**：URL単位の最短記録（ただしサーバーが必要になるので慎重に）。
- **リプレイ共有**：解答つきURL（`#s=`）を別パラメータにして「答え合わせ用リンク」を分離。
- **自動生成**：ランダム盤面 + BFS で「最短がN手ちょうど」の盤面だけ採用する。
- **アンチゴルフ賞**：最長経路でクリアする裏モードなど。

## Prototype Review

Mock を実際に触ったうえでの記録。企画時点の期待と、実装後に分かったことを分けて書く。

### 触ってみて良かった部分

- **RUN の瞬間は期待どおりだった。** 自分が並べた `F F R F F L F` が、ハイライトを進めながら1つずつ実行され、ロボットが盤面を走る。企画時に「ここが本体」と書いたが、実際そのとおりだった。3案の中でここだけが明確に「ゲーム」の手触りを持っている。
- **CRASH が気持ちよく失敗する。** 壁に突っ込んだ瞬間にロボットが赤くなり、`💥 CRASH — 5命令目の F で壁にぶつかった` と何命令目かまで出る。原因の特定に1秒もかからない。企画時は「失敗の種類が2つで済む」程度の期待だったが、**何命令目かを出す**だけで体験が一段良くなった。
- **想定していなかった収穫が Create モードの BFS だった。** 壁を置くたびに `✅ SOLVABLE / 最短: 14 commands` がリアルタイムで出る。これのおかげで、
  - 到達不能な盤面は SHARE ボタン自体が押せない
  - AUTO を押すと `PAR = 最短 + 1` が入る

  という状態になり、**共有される Challenge が必ず「解けて、かつ PAR -1 がちょうど1つ存在する」ことが保証される**。URL共有型ゲームの最大のリスクは「壊れた問題が拡散すること」だと実装中に気づいたが、それがエディタ側で自動的に潰れた。これは企画書には書いていなかった発見。
- **REMIX が本当に速い。** 共有された盤面を開いて REMIX → 壁を1マス足す → SHARE、で10秒かからない。連鎖が成立しそうな感触は確かにあった。

### 想定より弱かった部分

- **命令の入力が単純に面倒。** HARD（最短19命令）を解くには F を十数回押す必要がある。**考える時間より、指を動かす時間のほうが長い。** キーボード（F/L/R キー）を足してだいぶマシになったが、スマホでは逃げ場がない。企画時点ではまったく見えていなかった問題。
- **STEP を実装したが、ほとんど使わなかった。** RUN のアニメーションと軌跡表示で十分デバッグできてしまう。Cut List の1位に置いた理由はここ。
- **F / L / R だけだと、ゴルフの深さが浅い。** 最短経路はほぼ一意に決まるので、「短くする工夫」は実際には「無駄な回転を1つ削る」程度に落ち着く。企画時は「Code Golf 的な遊び」と書いたが、**現状は最短経路パズルであって、ゴルフではない。** `F3` のような繰り返し記法が入って初めて「書き方の工夫」が生まれるはず。
- 5×5だと最適解が一目で見えてしまい、7×7にすると入力が長くなる。**面白い盤面サイズと、快適な入力量が両立しない**というのが実装後にはっきりした一番の設計課題。

### 操作して気持ちよかった部分 / 面倒だった部分

- 気持ちよかった：RUN 中の命令ハイライトとロボットの移動が同期している瞬間。あと `PAR -1` のバッジが緑になる瞬間。
- 面倒だった：長いプログラムの修正。真ん中の1命令を消したいのに UNDO しかないので、末尾から作り直すことになる。**任意位置の削除・挿入は MVP に入れるべきだった。**

### 「もう一回」を感じたか

はっきり感じた。EASY を9命令で解いて `PAR -1` が出たあと、`8で行けないか` を反射的に試した。3案の中でこの反応が出たのは Route Golf だけ。

### Challenge を誰かに送りたいと思えるか / Remix したくなるか

- 送りたい：**思える。** URLが150文字程度で、貼るだけで相手が同じ盤面に立てる。`PAR -1 出せたら教えて` の一言が自然に添えられる。
- Remix したい：**思える。** ただし動機は「もっと面白くしたい」より「もっと意地悪にしたい」だった。壁を1個足して相手を CRASH させたくなる。この感情は共有の燃料としてかなり強い。

### ハッカソン本番で作る価値があるか

**ある。** 3案で唯一、画面が動き、失敗が笑えて、クリア後にもう一周する動機がある。
ただし本番では次の2つを MVP に含めないと、体験が企画書どおりにならない。

1. **繰り返し記法（`3F` など）** — 入力の面倒さを解消し、同時に「ゴルフ」を本物にする。この1機能で企画の弱点2つが同時に消える。
2. **プログラムの任意位置編集** — 長い解を直せないのは致命的。

逆に、Create モードの SOLVABLE / 最短判定は「余裕があれば」ではなく**最優先で入れるべき**というのが、触ってみて最も強く感じたことだった。
