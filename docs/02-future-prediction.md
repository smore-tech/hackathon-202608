# 企画2：「10秒先を当てる」自動戦闘予測ゲーム

> プロトタイプ: [../future-prediction/index.html](../future-prediction/index.html)

## 1. 一言で説明

**「この5体が殴り合ったら、最後に立っているのは誰か？」を戦闘開始前に当てるゲーム。**

プレイヤーは戦闘に一切介入できない。予想して、見守るだけ。

## 2. ゲームの目的

画面に3〜5体のキャラクターが並んでいる。それぞれ HP / ATK / SPEED を持つ。

プレイヤーは開始前に「最後まで生き残る1体」を選ぶ。START を押すと自動戦闘が始まり、数秒で決着する。予想が当たっていれば成功。

戦闘ルールはプロトタイプでは次の3行だけ。

- SPEED が高いほど攻撃間隔が短い（攻撃間隔 = 1000 / SPEED）
- 攻撃相手は **自分のひとつ右の生存者**（右端は左端へ / 円環ターゲット）
- HP が 0 になったら脱落。倒された相手を狙っていた者は、その次の生存者へ狙いを移す

**完全に決定論的**（乱数ゼロ）。同じ編成なら結果は必ず同じになる。「運が悪かった」という言い訳を消して、「読み違えた」だけを残すための設計。

## 3. 基本ゲームループ

```text
編成（数字と並び順）を見る
↓
誰が誰を殴るかの連鎖を追う
↓
生き残る1体を予想して選ぶ
↓
STARTを押す（ここから先は何もできない）
↓
自動戦闘を見守る
↓
的中 / はずれ
↓
次の編成へ
```

## 4. プレイヤーが考えること

- **まず「誰が一番先に死ぬか」を探す。** 生き残りを直接考えるのは難しいので、人は自然と脱落の順番から考えはじめる。
- **HPだけを見て裏切られる。** 最初は誰もが最大HPのキャラを選ぶ。だが円環ターゲットでは、狙われる相手は並び順で決まるので、HPが高くても集中攻撃を受ければ真っ先に落ちる。ここで「思考のモード」が切り替わる。
- **DPS（ATK × SPEED）で考えはじめる。** 「攻撃力18・速度4」と「攻撃力7・速度10」のどちらが怖いか。掛け算をした瞬間に、このゲームは数字を読むゲームになる。
- **並び順が意味を持つと気づく。** 同じ5体でも、並べ替えれば勝者が変わる。ステータスを見るゲームから、**関係を見るゲーム**に変わる瞬間がある。
- **誰かが落ちた瞬間に、狙いの連鎖が組み替わる。** ここが一番読みにくい。1体目の脱落までは計算できても、そこから先は連鎖が変わるので予想が崩れる。

## 5. 面白さの仮説

- **「予想する」は「操作する」より脳を使う。** 操作ゲームは反射で進めるが、予想ゲームは考えないと一歩も進めない。
- **介入できないことが緊張を作る。** 自分が選んだキャラのHPが削られていくのを、何もできずに見ているしかない。この無力感がそのままドキドキになる。
- **外れた理由が必ず盤面上にある。** 乱数がないので、「なぜ外したか」を必ず特定できる。理解できる失敗はリトライを呼ぶ。
- **観戦コンテンツとして絵になる。** HPバーが減り、ダメージ数字が飛び、キャラが💀になる。ゲームを知らない人が横から見ても、何が起きているか分かる。
- 編成を差し替えるだけで問題を無限に作れる。パズルと違って **コンテンツ生産コストが極端に低い**。

## 6. 不安要素

- **「見てるだけ」の時間が退屈になりうる。** 数秒とはいえ入力がゼロの時間があり、2回目以降は早送りしたくなる可能性が高い。
- **当てずっぽうでも当たる。** 3体なら1/3、5体でも1/5。1回の的中に価値を感じにくい。
- **決定論と読みやすさのトレードオフ。** 乱数を消したぶん納得感は上がったが、正確な予想には実質「暗算」が要る。真面目に計算すると重く、しなければ勘ゲームになる。この中間をどう作るか。
- 決定論なので同じ編成を2回遊ぶ意味がない。リプレイ性は「編成の供給」に完全依存する。
- キャラを増やすほど連鎖が複雑になり、「読めるから面白い」が「読めないから運」に転落する境界がある。

## 7. 1日ハッカソンでのMVP

- キャラクターカードの表示（名前 / 絵文字 / HPバー / ATK / SPEED）
- 決定論的な自動戦闘シミュレータ（先にログを全部計算してしまう方式）
- 戦闘前の予想選択（1体をタップ）
- 戦闘の再生：攻撃モーション、ダメージ数字、HPバー減少、脱落演出
- 的中判定と的中率カウンタ
- 編成3パターン + 「次の編成へ」

## 8. 時間が余ったら追加するもの

優先順位順。

1. **各キャラが「今誰を狙っているか」の明示**（プロトタイプでは 🎯 で実装済み）。ルール理解が段違いに速くなるので、実質MVP扱いでよい。
2. **ランダム編成生成。** 数十行で、コンテンツが無限になる。費用対効果が最も高い。
3. **早送り / スキップボタン。** 「見てるだけ」問題への最短の答え。
4. 予想の確信度を賭ける（「自信あり = 2倍」）。的中の価値が上がり、1/N の薄さが薄まる。
5. スキル（「HP半分以下で攻撃力2倍」など）を1〜2種類。読みの深さが一段増える。
6. 戦闘後の「なぜ外したか」ハイライト（決定的だった1撃を指す）。

## 9. 将来的な拡張案（今回は実装しない）

- **Daily Battle**：全員が同じ1編成を予想する。的中率をその日の全体平均と比べる。
- **予想の共有**：「俺はゴーレムに賭けた」をSNSに貼れる形式で。外れた人同士が盛り上がれる。
- **Seed / URL共有**：編成をURLにエンコードして「これ誰が勝つと思う？」と投げる。この形が一番拡散に向いている。
- **Ranking**：連続的中数のリーダーボード。
- **編成エディタ**：ユーザーが編成を作って問題として投稿。
- **観戦モード / トーナメント**：16体でトーナメントを組み、優勝者を予想する。
- **キャラのビルド要素**：ステータスを自分で振って、他プレイヤーの編成と戦わせる非同期対戦。

## Prototype Review

実際にブラウザで3編成すべて予想して遊んだうえでの所感。企画時点の想像とは分けて書く。

### 実際に触ると何が良かったか

- **円環ターゲットが当たりだった。** 検討中は「HPが低い相手を狙う」「攻撃力が高い相手を狙う」も試したが、どちらも **最大HPのキャラが必ず勝つ** という退屈な結論になり、1回遊べば攻略が終わってしまった。「ひとつ右を殴る」に変えた途端、3編成すべてで最大HPのキャラが敗退し、勝者が予想できなくなった。**並び順が読みの対象になる**のが効いている。
- **選んだキャラが削られる数秒が、想像していたよりずっと緊張する。** 特に編成A（3体）の決着は勝者の残りHPが8で、最後の一撃まで結果が分からない。「介入できない」がちゃんと機能していた。
- **外したときに理由を追える。** 乱数がないので、ログを上から読めば「なぜ落ちたか」が必ず特定できる。ここは狙いどおりだった。
- 画面が地味にならない。カードとHPバーと💀だけで、他2案よりはっきり「ゲームらしい」。

### 想定より弱かった部分

- **真面目に計算する気にはならなかった。** 暗算すれば解けるが、実際にやるとかなり面倒で、結局「速そうなやつ」「並び的に狙われにくいやつ」という直感で選んでいた。**予想ゲームのつもりが、体感は勘ゲームに近い。** 企画時に不安要素として挙げていたが、実際はもう少し深刻で、「考える楽しさ」まで到達する手前で止まっている。
- **2回目の再生は明確に長い。** 「もう一度見る」で同じ戦闘を見返したが、結果を知っているので5秒が長く感じた。早送りは「余裕があれば」ではなく必須に近い。
- **HPバーが減っていく間、プレイヤーの手はまったく動かない。** 見守る緊張は確かにあるが、それは初回だけで、慣れると単なる待ち時間になる。
- 5体編成は、脱落のたびに狙いの連鎖が変わるため、正直まったく読めなかった。体数を増やすと深くなるどころか運ゲー化する、という境界が3体と5体の間にあることがはっきりした。

### 本制作するなら最初に改善したいところ

1. **「読むための補助線」を1つ足す。** 例えばカードに DPS（ATK × SPEED）を最初から表示する、あるいは「このキャラを倒すのに何秒かかるか」を出す。暗算の負荷を1段下げるだけで、勘ゲームから読みゲームに戻せるはず。ここが最優先。
2. **予想を1体固定ではなく順位や2択にする。** 「1/5を当てる」は当たっても外れても手応えが薄い。「AとBならどちらが先に落ちる？」の2択のほうが、考える密度も納得感も高そうだった。
3. **早送りと、戦闘後の決定打ハイライト。** 待ち時間を削り、外した理由を画面が指してくれれば、リトライの動機が一気に強くなる。
4. 体数は3〜4体を上限にする。5体は「深い」ではなく「読めない」だった。
