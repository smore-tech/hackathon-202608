## Challenge URL の実測

Base64URL に載せた実際の長さ（Mock のサンプル問題を SHARE した場合）。

| | EASY | MEDIUM | HARD |
| --- | --- | --- | --- |
| Route Golf | 199 文字 | 217 文字 | 253 文字 |
| Pipeline Golf | 231 文字 | 263 文字 | 282 文字 |
| Regex Golf | 225 文字 | 233 文字 | 189 文字 |

3案とも Slack / X / メールにそのまま貼れる長さに収まった。**圧縮は不要**という当初の判断は正しかった。7×7盤面でも253文字で済むので、当面この方式の上限は問題にならない。

## 実装して分かった、3案に共通する最重要ポイント

**「Create モードに解の探索を入れないと、URL共有ゲームは破綻する」**

URL共有型の最大のリスクは、**解けない Challenge・PARが達成不能な Challenge が拡散すること**。
サーバーがないので、一度配られた壊れたURLは誰にも直せない。

3つとも Create 側に探索を入れた結果、これが構造的に潰れた。

| | 探索の中身 | 効果 |
| --- | --- | --- |
| Route | BFS（状態 = 位置 × 向き） | 到達不能なら SHARE 不可。AUTO で `PAR = 最短+1` |
| Pipeline | 幅優先探索（6手まで） | 到達不能なら SHARE 不可。AUTO で `PAR = 最短+1` |
| Regex | 総当たり解 `^(?:a|b|c)$` の構築と検証 | 両立不能なら SHARE 不可。AUTO で `PAR = 総当たり解の長さ` |

いずれも数十行で済む。**「時間が余ったら」ではなく MVP に入れるべき**というのが、3案すべてを触って最も強く感じたこと。企画時点ではどの企画書にも書いていなかった発見。

もう1つ、地味だが必須だったのが **クリップボードのフォールバック**。Mock を `file://` で開くと `navigator.clipboard` が使えないことが多く、テキスト欄に出して手動コピーさせる経路がないと SHARE が成立しない。

## 「短くしたくなるか」の実測比較

Code Golf を名乗る以上、ここが本質。

| | 総当たり／素直な解 | 賢い解 | 縮み幅 |
| --- | --- | --- | --- |
| Route (EASY) | 10命令（PAR） | 9命令 | **-1** |
| Pipeline (MEDIUM) | 5手（PAR） | 4手 | **-1** |
| Regex (EASY) | 32文字（PAR） | 4文字 | **-28** |

Route と Pipeline は、縮む余地が構造的に「1〜2」しかない。**現状の Route Golf は Code Golf ではなく最短経路パズル**で、ゴルフを名乗るには繰り返し記法（`3F` など）が要る。
一方 Regex Golf は何もしなくても桁で縮む。「もっと短く」という感情の強さは、実は評価表の順位と逆になっている。

## 結論（4つの観点）

### 最も安全に完成できる案 → **Regex Golf**

実装は1〜2時間。純粋関数の判定だけで、非同期処理もアニメーションもない。バグの入る隙がほぼない。
Create モードもテキストエリア2つで済むため、CREATE → SHARE → SOLVE → REMIX のループを最短で通しきれる。

### 最もエンジニア受けしそうな案 → **Regex Golf**

説明ゼロで通じ、腕前が文字数として即座に可視化され、横やり（「`\b` 使えば短い」）が入る余地がある。
`PAR 32` に対して `4 chars` が出たときの反応は、3案で最も大きかった。
ただし**エンジニア以外は1ミリも遊べない**ので、受け手を選ぶ。

### 最もデモ映えする案 → **Route Golf**

3案で唯一、画面が動く。会場で「この盤面、何命令で解ける？」と問いかけて、RUN でロボットが走り、壁に激突して笑いが起きる、という流れが作れるのはこれだけ。
Pipeline / Regex は、プロジェクター越しに何が起きているか伝わらない。

### 最もURL共有という特徴を活かせる案 → **Route Golf**

理由は2つ。

1. **盤面という「絵」がURLの向こうにある。** テキストのリストではなく、開いた瞬間に見て分かる形が復元される。URLを踏む価値が視覚的に返ってくる。
2. **Remix のコストが最も低く、動機が最も強い。** 壁を1個足すだけで新しい問題になり、しかも「相手を CRASH させたい」という感情が Remix を後押しする。

ただし Remix の**質**という意味では Regex Golf が優れている点は書いておきたい。Regex の Remix は「DO NOT MATCH を1件足す」＝**チーズ解を潰して問題を良くする行為**であり、連鎖するほど Challenge の品質が上がる。Route の Remix は難しくなるだけで、良くなるとは限らない。

## 判断が分かれるポイント

1. **見せる相手は誰か。** 会場全体・非エンジニアを含むなら Route。エンジニアだけの内輪なら Regex。
2. **Route Golf を「ゴルフ」にする時間があるか。** 繰り返し記法（`3F`）とプログラムの任意位置編集を入れられないなら、Route は最短経路パズルのまま出ることになる。ここに2〜3時間を割けるかが分岐点。
3. **1本に絞るか、2本出すか。** Regex Golf は1〜2時間で完成するので、Route を本命にしつつ Regex をサブで足す構成が現実的に取りうる。
4. **Challenge を作る人が誰か。** 自分たちだけで問題を用意するなら Route。参加者に作らせて回したいなら、作成コストが最も低い Pipeline / Regex が有利。
