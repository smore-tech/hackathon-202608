# 企画1：「あと1手」パズル

> プロトタイプ: [../one-move-puzzle/index.html](../one-move-puzzle/index.html)

## 1. 一言で説明

**「操作できるのは1回だけ。その1手で敵を全滅させてゴールに入れ」** という盤面パズル。

盤面を眺めて、正解の1手を見つけたら勝ち。それ以外は全部ハズレ。

## 2. ゲームの目的

5×5の盤面で、上下左右のどれか **1方向** を選ぶ。
自分は壁にぶつかるまで滑り続け、途中の敵を倒し、「向き変えタイル」に乗ると進行方向が変わる。

クリア条件は次の2つを **同時に** 満たすこと。

- 盤上の敵をすべて倒す
- 最後にゴールマスに入って止まる

「ゴールには着いたが敵が残っている」は失敗。ここが引っかけになる。

## 3. 基本ゲームループ

```text
盤面が表示される
↓
壁・向き変えタイル・敵・ゴールの位置関係を読む
↓
頭の中で1手ぶんの軌跡をシミュレートする
↓
方向を1回だけ選ぶ
↓
自機が滑っていく様子を見る（答え合わせ）
↓
Retry / Next Puzzle
```

## 4. プレイヤーが考えること

このゲームの中身は、ほぼ全部ここにある。

1. **まずゴールを見る。** 「ゴールに入って止まるには、どの方向から入ればいいか」を逆算する。
2. **次に敵を見る。** 「その進入ルート上に、敵は全部乗っているか？」を確認する。
3. **向き変えタイルを見る。** ここで思考が一段深くなる。直線では届かない場所に、タイルを経由すれば届く。
4. **軌跡を頭の中で線で描く。** 「上 → 右 → 下 → 左」のように、1手が長い1本の線になる。この線が全部の敵を通ってゴールで終わるなら正解。
5. **ハズレを見て、原因を1つに絞る。** 「敵が1体残った」のか「ゴールに届かなかった」のか。原因が明確なので次の1手が変わる。

つまりプレイヤーがやっているのは **「1本の線を頭の中で引く」** こと。手数管理でもリソース管理でもない。

## 5. 面白さの仮説

- 選択肢が4つしかないのに、正解が1つしかない。この「情報量の少なさに対する答えの鋭さ」が気持ちいい。
- 「滑る」ルールのおかげで、1手が長い軌跡になる。**入力は最小、結果は最大** という非対称が快感になる。
- 失敗しても盤面が変わらないので、「さっきのハズレ」がそのまま次のヒントになる。学習が1手ごとに進む。
- 1問30秒以内に終わるので、Daily Puzzle形式（1日1問）と相性が良い。
- スマホでは方向ボタン4つを押すだけ。操作の摩擦がほぼゼロ。

## 6. 不安要素

- **総当たりで解けてしまう。** 選択肢が4方向しかないので、考えずに全部試せば必ず解ける。しかも失敗にコストがない。これが最大の懸念。
- **問題を作るのが人力。** 面白い盤面はほぼ手作業で、しかも「解が1つだけ」を保証する検証が要る。1日で用意できる問題数がそのままボリュームの上限になる。
- **ルールの説明が要る。** 「滑る」「通過した敵を倒す」「向き変えタイル」は初見では分からない。チュートリアル1問目の設計が生命線。
- 難易度が上がると「向き変えタイルの数」に頼りがちで、盤面が記号だらけになって読みにくくなる恐れ。

## 7. 1日ハッカソンでのMVP

これだけは必ず実装する。

- 5×5盤面の描画（壁・敵・ゴール・向き変えタイル）
- 1方向を選ぶ入力（方向ボタン + 矢印キー）
- 滑り移動のシミュレーションと、1マスずつのアニメーション再生
- クリア判定（全滅 + ゴール）と、失敗理由が分かるメッセージ
- Retry / Next Puzzle
- ステージ3〜5問（手作りで可）

## 8. 時間が余ったら追加するもの

優先順位順。

1. **挑戦回数の表示**（「3手目で正解」など）。総当たり対策として最も効く。
2. ステージを5問 → 10問に増やす。
3. クリア時に軌跡を線で残して見せる（「なぜこの1手なのか」の説明力が上がる）。
4. 「1手」以外の要素の追加（押せるブロック、ワープ、1回だけ使えるジャンプ）。
5. 効果音（滑る音・撃破音）。体感の気持ちよさが一段上がる。
6. ステージのURL共有（盤面を文字列にエンコード）。

## 9. 将来的な拡張案（今回は実装しない）

- **Daily Puzzle**：1日1問。全員が同じ問題を解く。
- **成績の共有**：「◯手目で正解」を絵文字グリッドでSNSに貼れる形式に。
- **Seed / URL共有**：盤面を短い文字列にして、URLだけで問題を配れるように。
- **ステージエディタ**：ユーザーが作った問題を共有。解が1つであることの自動検証とセット。
- **自動生成 + ソルバー**：全4方向を総当たりして「正解が1つだけの盤面」を自動抽出する。実装は軽い割にコンテンツ問題を一気に解決する。
- **手数の拡張**：「2手モード」「3手モード」。思考の深さが指数的に増える。

## Prototype Review

実際にブラウザで3問通して遊んだうえでの所感。企画時点の想像とは分けて書く。

### 実際に触ると何が良かったか

- **軌跡アニメーションが想像以上に効いた。** 自機が壁で曲がりながら長い距離を走り、通りすがりに敵を倒していく数秒間が、そのまま「答え合わせ」になっている。「なぜその1手なのか」を文章で説明する必要がまったくなかった。
- **STAGE 3 の「→（右）」が最高の失敗になった。** 右を選ぶと、向き変えタイル2つを経由して敵を1体倒し、ちゃんとゴールに入る。**惜しくない失敗ではなく、惜しい失敗** になっている。「ゴールしたけど、敵が残っている」と出た瞬間に、盤面をもう一度見たくなる。この1問だけで企画の芯は伝わる。
- ルール説明を読まなくても、1問目を1回動かせば全部わかった。チュートリアルを文章で書く必要がない。

### 想定より弱かった部分

- **総当たりが想像以上に安い。** 5×5で自機が端にいると、そもそも合法な方向が2つしかない。実質「2択を2回試す」で解けてしまい、考える前に指が動く。失敗コストがゼロなので、思考を飛ばすのがいちばん速い攻略法になっている。企画時に「不安要素」として書いた項目が、触ったら不安ではなく **確実に起きる問題** だった。
- **1問の寿命が短すぎる。** 解けた瞬間に、その盤面には二度と用がなくなる。3問はおよそ1分半で尽きた。問題を作る速度がそのまま遊べる時間になる、というのが体感でわかった。
- 静止状態の画面がかなり地味。動くまで、これがゲームなのか設定画面なのか判別しづらい。

### 本制作するなら最初に改善したいところ

1. **失敗にコストを付ける。** 「◯手目で正解」を記録して常時表示するだけでいい。総当たりが恥ずかしくなれば、人は考えはじめる。Daily化するならこの数字がそのままスコアになる。
2. **選択肢を増やす。** 4方向のうち2つしか合法でないのは狭すぎる。「動かす駒を選んでから方向を選ぶ」だけで選択肢が一気に10〜20通りになり、総当たりが割に合わなくなる。ルールの追加コストは小さい。
3. **ソルバーを先に書く。** ステージを手で作って手で検証したが、これは1日ハッカソンでは絶対に破綻する。全パターンを回して「解が1つだけの盤面」を自動判定する仕組みを、ステージ作成より先に用意すべき。ロジックは既にあるので追加は数十行で済む。
